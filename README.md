# transcript-secret-scrubber

Find exact known values in explicitly selected transcripts and logs, including UTF-8, UTF-16LE and JSON-escaped forms. Default to dry run, and replace matched byte ranges only when `--apply` is supplied.

Removing an exposed credential from its original configuration does not remove copies in assistant logs. Exact matching helps clean known copies without printing those values into another transcript.

## Quick start

Requires Python 3.12 or newer. Create a private UTF-8 JSON array of known values in a separate file and restrict its permissions. There are no automatic home-directory searches or built-in credential locations.

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
python demo.py
python scrub.py --values private-values.json transcript.txt
python scrub.py --values private-values.json --apply transcript.txt
```

Keep the value file outside the selected targets and never commit it. The CLI refuses to scrub its own value input. Repeated target paths, hard links, symlinks and Windows reparse points are refused. Each file has a 64 MiB limit.

## Example output

Generated by `python -B demo.py` using a disposable transcript containing two encoded copies of one synthetic value:

```text
{"bytes": 79, "changed": false, "file": 1, "mode": "dry-run", "ranges": 2}
{"bytes": 79, "changed": true, "file": 1, "mode": "apply", "ranges": 2}
```

## How it works

The pattern builder creates raw and JSON-escaped forms, with both Unicode escaping styles, encoded as UTF-8 and UTF-16LE. Every overlapping occurrence is located and intersecting byte ranges are merged. Dry run opens targets read-only and leaves bytes and modification times unchanged.

Apply overwrites each matched range in place with the same number of ASCII replacement bytes. A verification read checks that the length is unchanged and no configured pattern remains. The file object is retained for existing append handles. Output contains only sequence numbers, counts and status; failures withhold exception text and values. Exit 0 means all requested operations completed; exit 1 means an input or verification failure.

## Limits

This finds known exact values, not unknown credentials. It does not handle base64, URL encoding, split tokens or UTF-16BE. Replacement preserves byte count rather than text encoding or JSON structure; UTF-16LE text can become unreadable in the matched regions. Stop writers before applying: the tool does not lock live logs against concurrent appends. A later file failure does not roll back earlier files. Values shorter than four characters and values that conflict with the replacement pattern are refused.

The tests exercise encodings, overlap handling, dry-run modification times, protected inputs, hard links and replacement collisions. No real credential files are used.
